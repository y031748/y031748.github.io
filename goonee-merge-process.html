1 원본 6개 조각 준비

10분(600초)짜리 mp4 6개를 만들어 채팅과 PC 폴더(GOONEE_MUSIC_MOVIE)로 각각 전달. 정지된 배경 이미지 + 오디오로 구성되어 있어, 순서만 맞으면 이어붙였을 때 화면 변화 없이 자연스럽게 연결됨.

2 1차 시도: VLC "여러 파일 열기 → 변환"

문제 발생

VLC 미디어 재생기에서 미디어 → 여러 파일 열기로 6개를 순서대로 추가한 뒤 변환(Convert) 실행. 재생목록에는 합계 1:00:00으로 정상 표시되어 진행하는 것처럼 보였음.

하지만 "대상 파일" 입력란에 원하는 출력 파일명을 직접 지정하지 못한 상태로 시작 → VLC가 기본 동작으로 되돌아가 소스 파일마다 개별적으로 "-converted" 접미사를 붙여 따로 변환. 즉 6개가 하나로 합쳐지지 않고 첫 번째 파일만 별도로 재인코딩되고 있었음.

goonee_1hour_part1of6-converted.mp4   ← 의도치 않은 개별 변환 결과

3 방향 전환: ffmpeg concat 방식으로 변경

VLC GUI의 "대상 파일 지정" 단계가 반복적으로 헷갈려서, 재인코딩 없이 정확하게 이어붙이는 ffmpeg concat demuxer 방식으로 전환. 이 방식은 화질 손실이 전혀 없고 처리 속도도 매우 빠름(스트림 복사만 수행).

  1. gyan.dev에서 ffmpeg 정적 빌드(essentials) 다운로드
  2. 압축 해제 후 bin/ffmpeg.exe를 영상 폴더로 복사
  3. 해당 폴더에서 터미널 실행 후 목록 파일 생성 + concat 실행

4 2차 시도: cmd 문법을 PowerShell에 입력

문법 오류

제공된 명령어가 옛 cmd.exe(배치) 문법(for %i in (...))이었는데, 실제 열려있던 터미널은 PowerShell이었음. PowerShell은 이 구문을 해석하지 못해 토큰 오류가 연속으로 발생.

(for %i in (1 2 3 4 5 6) do @echo file 'goonee_1hour_part%iof6.mp4') > list.txt

식 또는 문에서 예기치 않은 '2' 토큰입니다.
식에 닫는 ')'가 없습니다.
...(반복되는 파싱 오류)

5 최종 성공: PowerShell 문법으로 수정

성공

PowerShell 방식으로 목록 파일 생성 명령을 다시 작성 후 실행. 이어서 ffmpeg concat 명령으로 스트림 복사(재인코딩 없음) 실행 → 몇 초 만에 완료.

# 1) concat용 목록 파일 생성 (PowerShell)
1..6 | ForEach-Object { "file 'goonee_1hour_part$($_)of6.mp4'" } | Set-Content -Encoding ascii list.txt

# 2) 무손실 합치기
ffmpeg -f concat -safe 0 -i list.txt -c copy goonee_1hour_full.mp4

결과: goonee_1hour_full.mp4 생성 완료. VLC로 재생해 1:00:00 전체 구간이 순서대로(part1 → part6) 끊김 없이 이어지는 것을 확인.

6 배운 점 요약

・ VLC의 "변환" 대화상자는 대상 파일명을 명시적으로 지정하지 않으면 배치(개별) 변환으로 빠질 수 있음 — 다중 파일을 하나로 합치려면 대상 파일명 지정이 필수.

・ Windows 11 기본 터미널은 PowerShell인 경우가 많아, cmd 전용 배치 문법을 그대로 쓰면 실패함. 셸 종류를 먼저 확인해야 함.

・ 동일 코덱·해상도의 클립을 이어붙일 땐 ffmpeg -f concat -c copy가 재인코딩 없이 가장 빠르고 화질 손실이 없음.
